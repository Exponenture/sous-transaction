# AGENTS.md — engineering standards

Single source of truth for every contributor, human or AI. `CLAUDE.md` imports this file; Codex
reads it natively. If a rule here conflicts with a prompt, the rule wins — flag the conflict.

Django 5.2 + DRF backend API (`backend/`, project `config`, apps beside `config`), Postgres 16;
the API and DB run via docker compose. `core` holds shared plumbing (health, error handler,
request-id middleware). CI: GitHub Actions (`.github/workflows/ci.yml`) is the merge
gate; `bitbucket-pipelines.yml` mirrors it.

## Workflow
- `main` is always deployable. Nobody (human or agent) commits to it directly.
- One branch per concern: `feat/…`, `fix/…`, `chore/…`, `test/…`. Small PRs (aim < 400 lines).
- Every change lands via PR using the template: what / why / risk / tests / migration / rollback.
- Merge requires green CI (lint, tests, migrations check) and a human
  review. Squash merge; conventional-commit title (`feat(transactions): categorise on import`).
- Local gate: `make hooks` once (pre-commit runs ruff on staged files); `make test lint`
  before pushing.

## AI roles (separation of duties)
- **Builder** (Claude Code, own thread + branch): plans, implements against existing tests.
  **Never writes tests.** If a slice has no tests, stop and ask; describe missing cases for the Tester.
- **Tester** (Codex, own thread): writes all tests, black-box from `NOTES.md`, never from the
  implementation.
- **Reviewer** (Codex, fresh thread): adversarial PR review using `docs/prompts/adversarial-review.md`.
- **Human lead**: owns the spec, approves the plan, reviews every diff, triages every review
  finding (fix / accept-with-reason / defer), is the only one who merges.
- Agents never push to `main`, never merge, never edit an applied migration, never weaken a test
  to make it pass — if a test looks wrong, stop and say so.

## Task lifecycle (`PLAN.md`)
- Every task starts by copying `PLAN.template.md` to `PLAN.md` on the feature branch: `NOTES.md`
  is *what* (spec), `PLAN.md` is *who and in what order* (checklist).
- Work the steps in order. Tick a box only when its "done when" holds, appending the commit SHA.
  Agents tick their own steps; only the Lead ticks **Lead** steps. Record decisions and deferrals
  in `PLAN.md` as they happen.
- The penultimate step is always the adversarial review; nothing merges with an untriaged finding.

## Subagents
- Allowed for read-only exploration and for genuinely independent slices that touch disjoint
  files. The parent agent stays accountable: it reviews and summarises subagent output before
  anything is committed. Subagents never tick **Lead** steps, write tests (unless Tester), or merge.
- Not used in live/pairing sessions: the work must stay visible.

## Migration policy
- Migrations are committed files, generated by `make migrations`, reviewed like code. CI fails
  if a model change has no migration.
- Never edit or delete a migration that has reached `main`; add a new one.
- Schema and data migrations are separate files. Data migrations use `apps.get_model`, are
  idempotent and reversible (or explicitly `RunPython.noop` with a reason).
- Zero-downtime (expand/contract): add columns nullable or with a DB default → backfill → enforce
  `NOT NULL`/constraint in a later migration → remove old code → drop old columns last.
- Indexes on large tables: `AddIndexConcurrently` in a non-atomic migration.
- Renames are add + backfill + switch + drop, never an in-place rename on a hot table.
- Migrations run as a release step before new code takes traffic.

Stack and what each dependency does: `STACK.md`.

## Backend layout per app
`models.py` (data + DB constraints) / `serializers.py` (input validation, output shape) /
`services.py` (business logic) / `views.py` (thin HTTP glue) / `urls.py` / `admin.py` / `tests/`.

## Rules
- Tests first (TDD): the Tester writes the failing pytest tests, then the Builder writes the code. Name tests as behaviour.
- Auth is JWT (simplejwt): `POST /api/auth/token/` and `/api/auth/token/refresh/` (15 min access,
  1 day rotating refresh). Clients send `Authorization: Bearer <access>`; unauthenticated = 401.
  Session auth stays only for admin / browsable API. In tests use `auth_client` (force_authenticate).
- Thin views, fat services. Views validate via serializer, call one service fn, return response.
  Services are plain keyword-only functions that own transactions and side effects.
- Validation in serializers; business invariants ALSO enforced in the DB
  (`UniqueConstraint`, `CheckConstraint`, FKs with explicit `on_delete`). Never trust app code alone.
- Anything touching stock, balances, money, loyalty points or order state: `transaction.atomic`
  + `select_for_update()` on the rows you mutate, `F()` expressions for counters. Side effects
  (emails, webhooks, tasks) go in `transaction.on_commit`.
- Money: integer minor units (cents) or `DecimalField` + `Decimal`. Never float. Store currency.
- Datetimes: timezone-aware only (`USE_TZ=True`, `django.utils.timezone.now()`), never naive.
- Webhooks / payments / any retryable POST: idempotency key with a DB unique constraint;
  replay returns the original result. Verify webhook signatures.
- Serializers: explicit `fields = [...]`, never `"__all__"`; mark `read_only_fields`.
- Every endpoint: explicit permission (default is `IsAuthenticated`; `AllowAny` must be deliberate)
  and scope querysets to the caller (no IDOR). Every endpoint gets tests: happy path, validation,
  auth/permission.
- Errors always leave as `{"error": {"code", "message", "details"}}` (see `core/exceptions.py`).
- Avoid N+1: `select_related` / `prefetch_related` in viewset `get_queryset`.
- Migrations are committed files. Run `make migrations` after model changes; `make test` fails
  if any are missing. Add indexes for fields you filter/order on.
- No secrets in code. Config comes from env (`.env`, see `.env.example`).
- Log with `logging.getLogger(__name__)`; request id is attached automatically. Don't log PII.
  Sentry is on when `SENTRY_DSN` is set (`send_default_pii=False`).

## Done means
`make test lint` passes (backend pytest + ruff), new behaviour has tests, migrations committed, OpenAPI at
`/api/docs/` looks right.
